01Start Here

Mirror or Leech — pick the direction

Every task in this bot is one of two directions, and the command you type declares which. Everything else is a variation on those two.

The prefix tells the bot which downloader to use

Same direction, different engine. Choose based on what you're feeding it:

Three ways to hand it a source

  1. Inline — /leech <link>. The simplest form.
  2. By reply — reply to a message containing a link, a .torrent, or an .nzb with just /leech. Required for bulk and for Telegram range links.
  3. Bare command — send /leech alone and the bot replies with the full usage guide for that command.
Off by default

DISABLE_JD, DISABLE_NZB and DISABLE_SEEDR all default to True. On a fresh deploy the jd, nzb and Seedr commands refuse to run until the owner flips them off in Bot Settings.

Shortcuts

Every command has a short alias. /l = /leech, /ql = /qbleech, /m = /mirror, /s = /status, /c = /cancel. If the owner set CMD_SUFFIX, append it to every command: /leech1, /ql1. The exceptions are /restartall and /statusall, which are never suffixed.

03The Task Pipeline

What happens, in what order

Most confusing behaviour makes sense once you know the order of stages. A task runs these strictly in sequence, and one task is only ever in one stage at a time.

Four consequences worth internalising

  • One task = one batch. A torrent with 20 videos converts all 20, then uploads all 20. Nothing uploads early. To get file-by-file progress you need one task per file — see Recipes.
  • Encodes serialise, uploads don't. With several tasks running, task B starts encoding the moment task A's encode ends, while A uploads. That overlap is free — you just have to give the bot separate tasks.
  • Excluded files die after download, not before. The extension filter runs on completed files — and again after extraction — so it saves upload bandwidth and disk, never download bandwidth.
  • The lock pauses your other services. While an encode holds it, SABnzbd and JDownloader can be paused to free CPU, governed by THROTTLE_SERVICES (auto only on small hosts).

04Task Flags

Every task flag

Flags work on mirror and leech commands unless noted — /ytdl additionally takes -opt but not -e, -j, -d or -ad. Order doesn't matter, and they can be combined freely. Use the filter box in the sidebar to jump to one.

Naming & output

-nNew namenot for torrents

Rename the output. Torrents keep their internal names, so this is ignored there.

/leech <link> -n My Movie 2024
-nsName substitution

Regex find-and-replace across all filenames. Format find/replace/s where a trailing s makes it case-sensitive; separate rules with |. Omit the replacement to delete the text. Escape ^$.|?*+()[]{}- with a backslash.

/leech <link> -ns 1080p/4K | RARBG/ | \[grp\]/mine
-mSame directory

Collect several links into one folder so they upload as a single task. Also works per-link inside a bulk file.

/leech -i 3 -m Season 01
-upUpload destination

Mirror: an rclone path, a Drive id, a key from your UPLOAD_PATHS, or rcl/gdl to pick interactively. Leech: an extra copy destination — a chat id, @username or pm, with |topic_id for forum topics. The primary leech destination is LEECH_LOG_CHAT or -ud; see ch. 10. Use the full -100… id for channels and supergroups.

/leech <link> -up -1001234567890|42
/mirror <link> -up mydrive:Movies
-udNamed dump chatleech

Pick a primary leech destination by name from LEECH_DUMP_CHATS (yours merged over the owner's — yours win). A raw id or @username works too. An unknown name opens a button picker.

/leech <link> -ud movies
-gcDrive category

Choose the Drive category up front instead of waiting for the picker. Needs DRIVE_CATEGORY_MODE.

-ytYouTube upload

Upload the result to YouTube using your YT_* defaults from /usettings.

/mirror <link> -yt

Source handling

-iMulti-link

Process N consecutive messages, starting from the one you reply to. Each becomes its own task.

/leech -i 10
-bBulkreply required

Read links from a replied-to text message or .txt document, one per line, and spawn a task each. Optionally slice with start:end — a zero-indexed Python slice, so :2 is the first two and 1: skips the first.

/leech -b        # all links
/leech -b :2     # first two
/leech -b 1:     # skip the first
/leech -b 5:10   # links 6 through 10
-sSelect files

On torrents/nzb: opens the web picker so you choose which files to download. On /ytdl: shows quality buttons instead.

/qbleech <magnet> -s
-dSeed

Keep seeding after the torrent finishes. Give a ratio, a time in minutes, or both: 1.0, 1.0:60 or :60. Blocked when DISABLE_SEED is on.

/qbleech <magnet> -d 1.0:60
-adAllDebridneeds api key

Route through AllDebrid. Unlocks filehost links (1fichier, rapidgator…), or for magnets/torrents downloads from AllDebrid's CDN instead of peers — bypassing aria2/qBittorrent entirely. Great for dead torrents.

/leech <magnet> -ad
-au -apHTTP auth

Username and password for a protected direct link.

/mirror <link> -au user -ap pass
-hCustom headers

Extra request headers for direct downloads, as key: value pairs.

/mirror <link> -h Referer: https://site.com User-Agent: Mozilla/5.0
-optyt-dlp optionsytdl only

Raw yt-dlp API options as a Python dict, or key:value|key:value.

/ytdl <link> -opt {"format":"bv*+ba","writesubtitles":True}

Archives

-eExtract

Unpack archives after download. Add a password after the flag if needed.

/mirror <link> -e secret123
-zZip

Compress before upload, optionally password-protected. With both flags, extraction always runs first.

/mirror <link> -z secret123
-jJoin splits

Rejoin .001/.002 style parts. Runs before extract, so it usually pairs with -m.

/leech -b -j -m joined

Media processing

-ffFFmpeg preset

Run a named preset from FFMPEG_CMDS (or pass a list literal inline). Blocked when DISABLE_FF_MODE is on. Repeatable — pass it several times and each preset runs in turn on the same source, which makes side-by-side encoding tests easy. Full detail in ch. 08.

/leech <link> -ff av1
/leech <link> -ff t8 -ff t6 -ff t6q
-ca -cvConvert media

Blanket container/codec conversion. + limits it to listed inputs, - excludes them.

/leech <link> -cv mkv - webm flv
/leech <link> -ca mp3 + flac ogg
-metaMetadata

Write container metadata, pipe-separated. Supports {filename}, {basename}, {extension}, {audiolang}, {sublang}, {year}. Escape a literal pipe as \|.

/leech <link> -meta title={basename}|year={year}
-svSample video

Build a short preview. duration:part, default 60:4.

/leech <link> -sv 70:5
-ssScreenshots

Generate N stills across each video. Default 10.

/leech <link> -ss 6

Telegram delivery

-spSplit size

Override split size for this task. Accepts 2gb, 500mb, or raw bytes. Capped at your account's real ceiling — about 2 GB in bot mode, 4 GB when a premium user session does the upload.

/leech <link> -sp 2gb
-hl -ut -btTransmission mode

-bt bot only (2 GB cap). -ut user session only. -hl hybrid — user for files over 2 GB, bot below.

/leech <link> -hl
-doc -medUpload as

Force document (no compression, no preview) or media (streamable).

/leech <link> -doc
-tThumbnail

A direct image URL, a Telegram message link with a photo, or none to strip thumbnails.

/leech <link> -t https://i.imgur.com/x.jpg
-tlThumbnail layout

Grid of screenshots as the thumbnail, columns x rows.

/leech <link> -tl 3x3

Control

-f -fd -fuForce start

Skip the queue. -fd download only, -fu upload only, -f both.

/leech <link> -f
-rcfRclone flags

Pipe-separated rclone flags, overriding all others except --exclude.

/mirror <link> -rcf --buffer-size:8M|--drive-starred-only
-syncRclone syncclone only

Use sync semantics rather than copy.

/clone src:path -up dst:path -sync

Seedr

-seedrRoute through Seedrneeds account

Send a magnet through your Seedr account instead of peers. Needs SEEDR_EMAIL/SEEDR_PASSWORD and DISABLE_SEEDR turned off.

/leech <magnet> -seedr

Clone only

These apply to /clone with Telegram message links.

-fwdForward

Forward the messages instead of copying them.

/clone https://t.me/c/123/120-260 -ud A -fwd
-ctContent type

doc, med or all — which kinds of message to copy.

/clone https://t.me/c/123/120-260 -ct med
-exExclude extensions

Space-separated extensions to skip.

-mn -xnFilename filter

Regex that filenames must match (-mn) or must not match (-xn).

-mc -xcCaption filter

Same idea, applied to the message caption.

Before you clone Telegram links

Telegram clone runs on your session. Store it with /login (it's kept encrypted; /lockmysession locks it), then set destinations and filters under /usettings → Clone Settings.

Switched-off flags

The owner can disable -b (DISABLE_BULK), -i (DISABLE_MULTI), -d (DISABLE_SEED) and -ff (DISABLE_FF_MODE). The task then refuses to start rather than ignoring the flag.

No flag matches that filter.

05User Settings

/usettings — your personal defaults

Looking for one specific setting? Chapter 07 lists every button in both menus with its exact page and position, and it’s searchable.

These belong to your account and apply to every task you start, without needing flags. They are grouped into menus; each option has a Set/Change button and a Reset to fall back to the bot default.

Priority — read this once

For any setting that exists at both levels, resolution is: task flag → your user setting → bot config. A user-level value always beats the bot config, survives restarts, and ignores edits to config.py. If a setting seems stuck at an old value, check /usettings first and hit Reset.

Where config actually comes from

With DATABASE_URL set, the bot stores config in MongoDB and merges config.py on boot — but only for keys whose value changed since the last deploy. Editing config.py without redeploying leaves the database copy in charge. Changing a value through /bsettings applies immediately and avoids the whole question.

08FFmpeg Presets

Transcoding with -ff

FFMPEG_CMDS is a dict of named presets. Each name maps to a list of complete, independent ffmpeg commands, written without the leading ffmpeg.

The mistake everyone makes

Each string in the list is its own full command. Putting -del in as a separate list item makes it a second command with no input, which crashes the task after the encode finishes:

"av1": ["-i mltb.video ... mltb.mkv", "-del"]   # wrong — two commands
"av1": ["-i mltb.video ... mltb.mkv -del"]     # right — one command

The mltb placeholder

Filenames are written as mltb, which the bot swaps for the real path. The extension you attach decides both what the preset matches and what it produces.

TokenAs input — matchesAs output — produces
mltb.videoAny video file—
mltb.audioAny audio file—
mltb.mkvOnly .mkv.mkv output
mltbAnythingSame extension as input
mltb-tag.mkv—<name>-tag.mkv — a distinct name, ideal for comparisons

A working AV1 preset set

FFMPEG_CMDS = {
  "av1":   ["-i mltb.video -threads 8 -c:v libsvtav1 -preset 8 -crf 32
             -pix_fmt yuv420p10le -svtav1-params tune=0 -c:a copy mltb.mkv -del"],
  "av1hq": ["-i mltb.video -threads 8 -c:v libsvtav1 -preset 6 -crf 32
             -pix_fmt yuv420p10le -svtav1-params tune=0 -c:a copy mltb.mkv -del"],
  "hevc":  ["-i mltb.video -threads 8 -c:v libx265 -preset fast -crf 28
             -pix_fmt yuv420p10le -c:a copy mltb.mkv -del"],

  # sample encodes — 10 min from 2:00, no -del so the source survives
  "t8":  ["-ss 120 -t 600 -i mltb.video -c:v libsvtav1 -preset 8 -crf 32
            -pix_fmt yuv420p10le -svtav1-params tune=0 -c:a copy mltb-p8crf32.mkv"],
  "t6":  ["-ss 120 -t 600 -i mltb.video -c:v libsvtav1 -preset 6 -crf 32
            -pix_fmt yuv420p10le -svtav1-params tune=0 -c:a copy mltb-p6crf32.mkv"],
}

Besides named presets, -ff accepts a list literal inline. How many cores ffmpeg gets is set by FFMPEG_CORES.

Tuning notes

  • -preset — 0 (slowest, best) to 13. Each step up is roughly 1.5–2× faster and costs a little efficiency. Faster presets also parallelise worse, so CPU utilisation drops as you speed up.
  • -crf — quality target. Lower is better and bigger; 32→28 is roughly +40–60% file size. Change preset and CRF one at a time or you can't attribute the result.
  • tune=0 — optimise for how it looks rather than for PSNR. Almost always the right choice for content people watch.
  • enable-variance-boost=1 — steers bits toward detailed regions. Worth trying when output looks soft.
  • Avoid lp=N — it's a 0–6 parallelism level, not a thread count. Out-of-range values are silently clamped.
Careful with -map 0

It looks like the right way to keep every audio and subtitle track, but it also feeds cover-art and thumbnail image streams to the video encoder, which fails the whole job with The maximum allowed frame rate is 240 fps. If you need all tracks, be explicit — the ? makes each optional:

-map 0:v:0 -map 0:a? -map 0:s? -map 0:t?  -c:a copy -c:s copy -c:t copy

With a single audio track and no subtitles, just omit -map — ffmpeg's default selection does the right thing.

Progress reads wrong on sampled encodes

Percentage is computed against the full source duration, so a -t 600 sample of a 2-hour file tops out near 8% and shows a wildly inflated ETA. Multiply the displayed percentage by source_duration ÷ sample_duration for the real figure.

09Queues & Throughput

Getting the machine busy without filling the disk

Three settings shape concurrency, and they interact with the pipeline in a way that isn't obvious. QUEUE_ALL caps downloads and uploads together; the other two cap each end separately. 0 means unlimited everywhere.

The disk trap

QUEUE_DOWNLOAD = 0 with a 50-link bulk file downloads all fifty at once, while ffmpeg drains them one at a time. Every source sits on disk for hours waiting its turn, and the volume fills. Encoding is nearly always the bottleneck — stage only a few files ahead of it.

A sane starting point for transcoding work

QUEUE_ALL      = 0   # no combined cap
QUEUE_DOWNLOAD = 3   # stage ~3 files ahead of the encoder
QUEUE_UPLOAD   = 1   # one upload at a time, keeps parts in order

The encoder never waits on a download, disk stays bounded at roughly three sources plus outputs, and because -del removes each source after its encode, space frees as the batch moves.

Why uploads overlap encodes for free

The ffmpeg lock is released the moment an encode finishes — before the task waits for an upload slot. So the encoder is never blocked by an upload backlog:

Task A  [encode ████]──────[upload ░░░░]
Task B          [encode ████]──────[upload ░░░░]
Task C                  [encode ████]──────[upload ░░░░]

This only happens across separate tasks. One task containing 20 files gets no overlap at all.

CPU utilisation

Seeing 70% rather than 100% during an encode is usually normal — fast presets have less to parallelise. Two things are worth checking before chasing it:

  • Load average lies in containers. /proc/loadavg isn't namespaced, so any load figure you see is the whole host's, not your slice.
  • Thread count is yours to set. FFMPEG_CORES (default auto, 60% of the CPUs the container may use) pins ffmpeg and sets -threads. The CPU list respects cpusets but not CFS quotas, so on a quota-limited container set it explicitly.

Total throughput, not peak utilisation, is the number that matters. Because SVT-AV1 scales sublinearly, two 4-core encodes generally beat one 8-core encode — though the bot serialises encodes by design, so that needs a code change.

10Leech Destinations

Where files actually land

There are three separate destination settings with the same name and very different behaviour. Confusing them is the most common leech problem.

Set atRoleBehaviour
/bsettings → LEECH_LOG_CHATPrimaryEvery leech uploads here regardless of which chat the command came from
-ud NAMEPrimary, per taskOverrides LEECH_LOG_CHAT for this task, by name from LEECH_DUMP_CHATS
-up flagExtra copyPer-task copy destination, sent after upload
/usettings → Leech Dump ChatsExtra copiesEvery upload is also copied to all of your saved dump chats

If LEECH_LOG_CHAT is empty and you pass no -ud, files go to whichever chat you typed the command in. That's why setting only your own dump chats looks like they're ignored — they were only ever configured to receive copies.

Always use the full id

A bare 1234567890 is read as a user id. Channels and supergroups need the -100 prefix — a missing prefix is what produces PARENT_PEER_INVALID and USER_NOT_PARTICIPANT.

The 4 GB checklist

Premium splits need all of these true, and any one failing silently drops you to 2 GB:

  1. USER_SESSION_STRING generated from an account that holds Telegram Premium, using the same TELEGRAM_API/TELEGRAM_HASH as the bot.
  2. The user client started cleanly — look for WZ User : [name] Started! in the log.
  3. TRANSMISSION_MODE is user or both, and you didn't pass -bt.
  4. Destination is a supergroup or channel, not a PM — the user account can't post to a bot's DM.
  5. Both the bot and the premium account are members of that chat.
  6. Re-enter the split size after premium is detected — a value clamped to 2 GB earlier stays stored.
Fast check

Open /usettings → Leech Split Size → Change. The input prompt ends with PREMIUM_USER: true or false. Note 4 GB means 4,194,304,000 bytes and displays as 3.91GB — that's correct, not a failure.

Split parts arriving out of order

With USE_HYPER on, uploads within a task run concurrently, and nothing re-sequences them when LEECH_LOG_CHAT is set — so part002 can land before part001. Setting USE_HYPER = False makes uploads sequential and fixes the order. You only give up real throughput if HELPER_TOKENS is populated; with a single client, hyper mode was never running uploads in parallel anyway.

11Recipes

Worked examples

Batch-transcode a list of links

Put one link per line in a .txt, send it as a document, then reply to it:

/l -b -ff av1

Each link becomes its own task, so encodes serialise while uploads overlap, and every finished file is durable on its own. Resume after a crash by skipping what's done — the number is how many to skip, not the link number:

/l -b 10: -ff av1     # continue from the 11th link

Compare encoder settings before committing

Because -ff is repeatable, one command produces every variant from one download:

/l <link> -ff t8 -ff t6 -ff t6q
movie.mkv              ← source, kept
movie-p8crf32.mkv      ← preset 8, CRF 32
movie-p6crf32.mkv      ← preset 6, CRF 32
movie-p6crf28.mkv      ← preset 6, CRF 28

Compare the two CRF-32 files first — only the preset differs, so any gap is pure encoder effort. If they match, CRF was your variable all along.

Pick files out of a big torrent

/ql <magnet> -s

Opens the web picker. Deselect what you don't want, confirm, and only the rest downloads.

Season pack into one folder, renamed

/l -i 12 -m Show S01 -ns 1080p/ | \[grp\]/ -ff av1

Rescue a dead torrent

/l <magnet> -ad -ff av1

AllDebrid fetches it server-side and you pull from their CDN — peers become irrelevant.

Copy a range of Telegram messages

/clone https://t.me/c/123/120-260 -ud movies -ct med -fwd

Needs your stored session (/login). -ud picks one of your Clone Settings destinations by name.

Send each leech to a different channel

/l <link> -ud movies
/l <link> -ud series

Define the names once in /usettings → Leech Settings → Leech Dump Chats, or bot-wide in LEECH_DUMP_CHATS.

Drop junk from every download

/bsettings → EXCLUDED_EXTENSIONS:

exe msi dll scr bat cmd apk jpg jpeg png gif bmp webp tif svg ico nfo txt url lnk htm html
Keep entries long

Matching is a suffix test against the whole filename, not a real extension check. ts would also delete .mts and .m2ts videos. Every entry above is safe; short ones like ts, rs, db, so are not.

12Gotchas

Things that cost an afternoon

A config change did nothing

Settings resolve task flag → user setting → bot config. A value in /usettings overrides config.py permanently and survives restarts. Check there first and hit Reset.

ValueError: '-i' is not in list

-del was written as its own list item. Move it inside the command string it belongs to.

The maximum allowed frame rate is 240 fps

-map 0 sent a cover-art stream to the video encoder. Use -map 0:v:0 plus optional 0:a? 0:s? 0:t?, or drop -map entirely.

Split size snaps back to 2 GB

Premium wasn't detected when you entered the value, and the clamped result was saved. Confirm PREMIUM_USER: true, then re-enter it. Walk the checklist in ch. 10.

Files land in the wrong chat

Only LEECH_LOG_CHAT (or -ud) is a primary destination. Your own dump chats and -up just receive copies; with no primary set, files go to the chat you typed in.

CHANNEL_INVALID when forwarding

The client doing the copy can't resolve that chat. Add both the bot and the premium account to it, and use the full -100… id.

part002 posted before part001

Concurrent uploads with USE_HYPER on. Set it to False unless HELPER_TOKENS is populated.

The log names the same file twice

A cosmetic race — the uploader stores the current filename on a shared field, so overlapping uploads report the newest name. Both files did upload.

/cancel GID does nothing

Cancel and select are wired to the /c_<gid> and /sel_<gid> links that appear on each status message. Tap those.

jd, nzb or Seedr commands refuse to run

DISABLE_JD, DISABLE_NZB and DISABLE_SEEDR default to True. Turn them off in /bsettings.

b: / u: / h: on -up changes nothing

In the current code the prefix is parsed and then overwritten by TRANSMISSION_MODE and the -bt/-ut/-hl flags. Use those instead.

/mediainfo, /imdb and friends don't respond

They're plugins now. Enable them from /plugins.

Bulk says "Bulk Empty!"

-b reads from a replied-to message or .txt document. Sent on its own it has nothing to read.

-b 1:2 gave one link, not two

It's a zero-indexed Python slice. First two is :2; 1:2 is the second link alone.

A crash lost hours of encoding

Converted files are only uploaded after the whole task's encoding finishes, and the downloads directory is wiped on restart. Use one task per file (bulk mode) and enable INC_TASK_RESUME.

Progress stuck at a few percent

Expected on a -t-limited sample — percentage is measured against the full source duration. Nothing is wrong.
